# v2.2.0 validation

Local validation on macOS / Python 3.14.5:

- 41 unittest cases passed, including a 1100-layer chain and legacy output encoding.
- Actual dictionary, mask, default numeric fallback, streaming wordlist directory, AES and bkcrack KPA recovery were exercised with temporary fixtures.
- Output collisions preserve old files in backups; simulated publication failure restores old files.
- Partial decryption/extraction, corrupt data, traversal/symlink members, resource limits and incorrect inner passwords were checked.
- Legacy short-plaintext CRC32 recovery, dictionary lookup and ZIP LZMA fallback were checked.

Password-verification comparison against main (v2.1.0 / `22e1f716982371ac126c858396bec8e58509883b`):

- Same interpreter, optional dependencies and `test02.zip` fixture.
- Six alternating rounds per version, 5000 incorrect candidates per round.
- Baseline median: 0.08836 seconds.
- v2.2.0 median: 0.08822 seconds.
- Ratio (new / baseline): 0.9985.

The difference is within normal timing noise. This is a focused hot-path check, not a guarantee for every archive, platform or workload. Small-entry verification retains the existing read path; large-entry verification and extraction use bounded buffers.

Run the regression suite with:

```sh
python3 -m unittest discover -s tests -v
```

The GitHub Actions matrix additionally checks Linux/macOS/Windows, Python 3.7/3.10/3.14, and standard-library-only operation. Optional integration tests explicitly report skipped when their dependencies are unavailable.
